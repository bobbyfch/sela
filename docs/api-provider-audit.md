# Public API directory audit

**Reviewed:** 2026-10-19 · **Scope:** Books, News and Games & Comics directories on publicapis.dev and the public-apis GitHub README. These are changing discovery indexes, not evidence that an API works or grants reuse rights.

## Method and coverage

All category pages and their pagination were inventoried. The directory metadata was used for a first-pass relevance and suitability screen across every listed name. Primary-provider documentation and requests were checked in depth for Sela-relevant candidates and active providers (summarized below and in [library-sources.md](library-sources.md)). The 301 inventoried rows were **not** all independently endpoint-tested or individually checked against every licensing, quota, CORS and maintenance criterion. Those long-tail entries are rejected at the relevance screen; they are not represented as verified APIs. This distinction keeps the audit reproducible without inventing facts for names that are only directory labels.

Counts include duplicate names that appear in both directories: Books 48, News 55 and Games & Comics 198, for 301 rows total. The publicapis.dev Games & Comics category rendered 89 entries over four pages on the review date; the GitHub README contained 109.

## Active integration boundaries

- Books remain normalized to catalog records with separate text/cover rights, attribution, paging, request timeout, bounded retry and stale-cache fallback. A failed provider is not silently treated as empty data.
- News uses ANTARA and Guardian RSS headlines/excerpts with publication/source information and original links. No full article body is ingested.
- Religious text remains the existing attributed local edition set: Quran source editions, World English Bible, Douay-Rheims, Dhammapada, Bhagavad-Gita and Analects. English editions are not represented as Indonesian translations.
- No directory-only game service or comics metadata API was integrated as if it supplied licensed comics.
- Open Library's live search endpoint returned HTTP 200 with wildcard CORS during this review, so Sela now calls Open Library directly. Other Open Library endpoint CORS behavior still needs independent browser checks. The direct Gutendex GET smoke request timed out after 20 seconds in this environment; it was inconclusive, so Gutendex remains behind the existing CORS.dev bridge with retries, caching and local fallback. The Guardian RSS feed also needs a bridge because its publisher origin does not allow browser reads. These public bridges receive only public search terms or feed URLs, without credentials or private shelf/reader data. CORS.dev publishes request limits and a privacy policy, but did not receive an independent security audit here; users should avoid sending personal or sensitive search terms. A trusted first-party proxy or disabling the bridge-dependent features remains the safer option if that third-party trust boundary is unacceptable.
