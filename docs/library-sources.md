# Discover inside your personal reader

The public Books, News and Games & Comics directory inventory, provider decisions and research limits are recorded in [api-provider-audit.md](api-provider-audit.md). The full implementation checklist is in [comprehensive-refactor-checklist.md](comprehensive-refactor-checklist.md).

Discover follows one visible sequence: choose a source card, choose one of the collections that source supports, then optionally choose a topic. The active source and collection stay in the results heading, so “recently added” or “top reads” always identifies its catalog. There are no source dropdowns in the main flow. Tap a cover for edition details; read open editions in a temporary preview or save them to the private shelf. Metadata-only records link to their source instead of pretending the book can be downloaded. Catalog modules load only when Discover opens, outside the SDK's main entry.

### Public API directory review · 2026-10-19

The [publicapis.dev Books](https://publicapis.dev/category/books), [News](https://publicapis.dev/category/news) and [Games & Comics](https://publicapis.dev/category/games-and-comics) lists and the [public-apis repository](https://github.com/public-apis/public-apis) were used as discovery indexes. A directory listing is not proof an endpoint is current, keyless, CORS-enabled, reusable, or suitable for serving full text. The app therefore adds only sources whose actual browser-facing flow was validated and whose content rights are represented honestly.

The book review kept Gutendex, Open Library, Wikisource, OpenStax, GITenberg and BookRank. The flow exposes only the topics each source handles: Gutendex topics; Open Library subject shelves for its “Browse all” and hidden-gem collections; and selected BookRank ranked lists. On 2026-10-18, BookRank's live rankings index reported 47 category endpoints, and all 47 files returned HTTP 200 with items; Sela's configured allowlist matches those category slugs. The categories include cooking, music, personal finance, science, religion and comics. Comic and graphic-novel results remain attributed catalog links; their text and artwork are not copied. Open Library's CORS-bridged subject endpoints were live for nonfiction, religion, technology, psychology, health, nature, business and self-help; the science subject bridge returned HTTP 521 during that earlier check, so science remains with BookRank's verified popular-science feed only. A direct Open Library `search.json` request returned HTTP 200 and wildcard CORS on 2026-10-19, so current catalog searches use the provider directly; CORS on every other Open Library endpoint was not verified. The direct Gutendex smoke request timed out after 20 seconds in this environment, so Sela retains its CORS.dev bridge for Gutendex queries, with cache and local fallback. Standard Ebooks' feed returned HTTP 200 without CORS, while the bridge returned HTTP 403, so it was removed from the live source picker. Google Books' keyless request was rate-limited during the review and its official API documentation requires a key for public data, so it is not an active source in this static client. The DOAB API returned HTTP 403 during the review. Those providers are not presented as working integrations.

For news, the working publisher RSS feeds are ANTARA and The Guardian through the documented public RSS bridge. Category tabs call only their own category feed; in Indonesian, topic-specific ANTARA feeds are tried first, followed by topic-filtered ANTARA headlines and the matching Guardian category. The source fallback preserves that selected topic. Noozra's unauthenticated article endpoint returned HTTP 401 during the review, so it was not added. The broader `public-apis` index also contains unrelated game APIs, key-gated comic metadata services and services whose data licenses do not permit redistribution. These are not treated as open-book sources; no comic scans or book files are scraped from directory entries. The existing reader dictionary feature already covers contextual word lookup without expanding Discover's source list.

The collection step is source-aware: Project Gutenberg offers popular and recently added catalog records; Open Library offers daily trends, hidden gems or browse-all before its subject filters; OpenStax offers its curated open textbooks; and Sela picks, Wikisource, GITenberg, BookRank, Indonesian tech links and OPDS each expose only their relevant browse modes. Search stays within the chosen source. BookRank cards are outbound discovery records; they are not presented as readable or downloadable editions. Open Library requests cover art only for displayed results and respects its request guidance; the cover image's rights are separate from metadata.

Home’s “On this day” widget requests the localized Wikimedia history feed. News categories are separate, accessible tabs: selecting one category loads only that category, while up to four chosen topics remain in their own tabs and result lists. Unit and browser tests verify category isolation, switching, keyboard navigation, and responsive layout. Indonesian automatic news tries the matching ANTARA RSS section (Humaniora for books, Tekno for science/technology, Warta Bumi for nature, Lifestyle for art, Hiburan for culture), then ANTARA latest headlines filtered to that topic, then the matching Guardian RSS category. For other app languages, Sela uses the Guardian category feed. The source picker can prefer ANTARA or The Guardian; a missing or empty preferred feed falls back to the other publisher, and ANTARA is disabled outside Indonesian so local headlines are not silently mixed into a translated interface. Live check on 2026-10-18: all six configured Guardian category feeds returned HTTP 200 through the proxy; five configured ANTARA section feeds returned HTTP 200 with `Access-Control-Allow-Origin: *`. Guardian uses `proxy.cors.dev` because its RSS origin does not permit browser reads; the proxy documents no-key GET access with a 1 MiB response cap. Requests omit credentials and the parser allowlists article/image hosts. The last successful results are cached per language, category and source. A publisher's supplied image is shown only when present; otherwise Sela uses its neutral placeholder. The quote shelf uses Wikiquote search and preserves the source-page link. These feeds remain optional and do not affect the local bookshelf.

## Faith and scripture readings

The faith preference is optional, stored only in this browser’s Sela personal settings, and defaults to “No preference”. Sela never infers a user’s religion. The selector offers the six religious categories officially recognized in Indonesia: Islam, Protestant Christianity, Catholic Christianity, Hinduism, Buddhism and Confucianism. When chosen, Home loads a sourced reading only when a compatible public edition is available; every passage identifies its actual text language, edition and source. The “Browse the Quran” action loads a selected surah on demand and opens it as HTML in Sela Viewer. QuranEnc offers Indonesian (`indonesian_affairs`, identified by its API as the Kementerian Agama translation), English (Saheeh International) and Japanese (Saeed Sato) translations. Its API terms require attribution and version retention, prohibit changing the published translation, and ask clients to follow new issued versions. The Islam Home shelf also has Quran chapters and daily adhkar collections; the latter use Buruja’s published Arabic, transliteration and English meanings with the source references retained. The English meaning is explicitly identified and is not silently machine-translated for Indonesian or Japanese UI users.

The Quran reader pairs Arabic text with the selected, attributed QuranEnc translation. Its per-surah study link opens Qur’an Kemenag, which publishes the surah’s Arabic, Indonesian Latin transliteration, translation and tafsir; the published Latin method follows the joint Ministry of Religious Affairs and Ministry of Education transliteration standard. The reader also links to LPMQ publications on the meanings of all surah names, Makki/Madani revelation periods, and asbabun nuzul. These are source references, not Sela-written tafsir or a complete per-surah chronology. The official color-coded tajwid and Latin reading guide currently linked here covers Juz Amma only; Sela does not apply unsourced tajwid labels to other chapters. Qur’an Kemenag’s developer API offers official Mushaf Standard Indonesia text, translations and tafsir, but its portal requires registration and a formal access request, so no API token is embedded in this static public client. The Home story shelf is a selection of Qur’anic passages with explicit surah/verse references; selecting a card opens that cited passage in the reader rather than adding unsourced narrative details. LPMQ’s “Kisah Para Nabi Pra-Ibrahim” publication is clearly labeled as limited to prophets before Ibrahim.

The other adapters are explicit about limits. Protestant readings use the public-domain World English Bible in English. Catholic readings link to the official Lembaga Alkitab Indonesia API but stay outside the in-app reader until its access credentials and edition terms are available. Buddhist readings use Bhikkhu Sujato’s English passages from SuttaCentral. Hindu readings show Sanskrit, or the API’s English rendering when English is selected. Confucian readings link to the Analects in the Chinese Text Project; its API requires a registered key/IP, so Sela does not pretend to load it directly. Source language stays visible when it differs from the selected UI locale; Sela does not machine-translate sacred texts or present paraphrases as scripture. eBible.org lists Indonesian AYT, but its stated CC BY-ND-NC terms prohibit commercial use, so this reusable adapter does not silently bundle it. The official Qur’an Kemenag API is another future adapter option, but currently requires a registered request; QuranEnc’s Kemenag-labelled edition is used for the no-key public client. Provider availability is not a religious authority, and unsupported or unavailable editions retain a direct source link instead of fabricated fallback text.

`src/scriptures.ts` exports `getDailyScripture`, `getQuranChapter`, `getQuranTranslations`, `getIslamicReadingCollection`, `openIslamicCollection`, `createScriptureDocument`, and the provider registry from the `@bobbyfch/sela/scriptures` package path. The adapters are framework-independent and open safe HTML reading documents through Sela Viewer with `format: 'html'`. The Bhagavad Gita API currently states that its hosted service is free for non-monetized applications; replace or disable that adapter before monetizing a host. For any faith-specific deployment, verify each provider’s current translation license and edition metadata before adding offline bundles or changing the text.

Discover currently presents **9 source cards**. Wikisource language choices share one provider; Open Library's browse modes share one catalog. Results deduplicate IDs within the active source; SHA-256 prevents saving identical files twice. Different editions are not silently merged.

The English *Metamorphosis* edition numbered 5200 is not in Selected classics: Project Gutenberg identifies its David Wyllie translation as copyrighted. A free-to-read listing does not automatically grant permission to fetch, retain, or redistribute its text.

## Community reading directories reviewed

The three user-supplied “awesome” repositories are indexes, not a license grant for every linked project. Sela uses the CC BY 4.0 EbookFoundation Indonesian book-list file only to curate a small set of **outbound links**; the entry cards retain an explicit per-resource rights warning and never fetch those sites' content. GitIndonesia's repository list was used as a discovery map, not copied into the app. The `sindresorhus/awesome` Books section is likewise a discovery index. `rujukan/made-in-indonesia` currently shows no repository license, so Sela links to it only as a research lead and copies neither its descriptions nor project code. No whole app, book, illustration, dataset, or repository was transplanted based on its public GitHub visibility. A public repo grants viewing/forking through GitHub, while reuse, redistribution, and derivative-work permissions depend on the repository's license; see [GitHub's licensing guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).

**Read** fetches a bounded file and opens an ephemeral preview. Closing cleans up viewer resources; it does not add the book to IndexedDB. **Download & add to shelf** validates and stores a copy in the private shelf. Metadata-only cards offer **View edition**. Discover shows locally generated cover artwork immediately, then loads provider art near the viewport from HTTPS allowlisted Gutenberg and Open Library endpoints. Imported books remain local: Sela does not send their ISBNs to a cover service. Text transcriptions lack EPUB/PDF publisher layout fidelity.

## Personal catalogs

Save named HTTPS OPDS profiles for compatible Calibre-Web/Kavita/Komga servers. Optional username/password stay in the current sheet/session and are not persisted. Authorization is scoped to the origin where credentials were supplied; external acquisition/navigation links do not inherit it. Servers must permit the Sela origin and required auth headers through CORS. HTTP servers cannot be fetched from an HTTPS app. Importing a file is still available when remote access fails.

Catalog profiles are local preferences. OPDS discovery does not itself sync progress; optional manual WebDAV backup is a separate connection. Nothing bypasses lending restrictions, DRM, provider quotas or membership.

## Book-cover source and size review · 2026-10-21

Discover uses the official [Open Library Covers API](https://openlibrary.org/dev/docs/api/covers) for records that include a cover identifier. Its `S`, `M`, and `L` URL variants are intended sizes, and its guidance asks clients to avoid crawling and to link back to Open Library. Sela maps **SD** to `M` and **HD** to `L`; the same resolved URL is used for the visible image and a user-requested download. In a live check on 2026-10-21, the documented sample ISBN returned 180×183 pixels (10,729 bytes) for `M` and 465×475 pixels (50,473 bytes) for `L`; both responses were JPEG and allowed CORS. Other sources that expose one fixed cover URL keep that URL for both settings rather than claiming a larger rendition. Imported personal books are not sent to any cover lookup service.

The six suggested projects/services were checked individually:

- [Apple Books Covers](https://github.com/janlarres/apple-books-covers) is a GPL-3.0 Calibre plugin, not a cover API. Its README describes searching Apple’s iTunes API by ISBN, then title/author, and warns of roughly 20 requests per minute. Apple’s [iTunes Search API terms](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/) limit book promo artwork to promoting the matching store item and require a direct store link/badge; Sela therefore does not expose it as a general downloadable cover source.
- [Open Library Covers API](https://openlibrary.org/dev/docs/api/covers) is the selected source because its official endpoint provides explicit `S/M/L` renditions without a Sela API key and documents how to link and request covers. Sela only requests covers for visible catalog results and uses `default=false` so missing art falls back cleanly.
- [Google Books API](https://developers.google.com/books) describes `imageLinks` for available thumbnail, small, medium and large images, and its API docs require an API key for public data. Sela’s previous source review also observed rate limiting on keyless calls, so it is not an active source in this static client. The cover resolver accepts Google’s documented image URL forms if a future trusted catalog provides them, while preserving the provider’s selected thumbnail/large URL.
- [BeYourCover](https://beyourcover.com/api-docs) is an authenticated, credit-based AI cover generator with an upscale operation. It creates new publisher artwork rather than finding the cover of an existing edition, so it does not belong in catalog lookup or a personal reader’s cover download flow.
- [w3slley/bookcover-api](https://github.com/w3slley/bookcover-api) is a separately hosted API that searches Goodreads and returns Goodreads image URLs, with small/medium/large request parameters. It depends on scraping a third-party catalog and does not establish an image reuse grant or stable service contract for Sela, so it is not called from the app.
- [amazon-book-cover-grabber](https://github.com/drewmarsh/amazon-book-cover-grabber) is a pair of shell/PowerShell scripts that retrieve high-resolution images from Amazon using a product URL, ASIN, or ISBN. It is not a browser API, and the repository does not establish a supported cross-origin download or cover reuse contract; Sela does not scrape Amazon.

Cover quality is a display-and-download preference stored locally on the device. Cover frames retain a fixed book proportion and use `object-fit: contain`, so a provider image with a nonstandard ratio is letterboxed rather than stretched. The size selector is advisory for sources that only expose one image; download filenames include the selected `SD` or `HD` choice, and the download request uses the exact URL currently displayed.

### Sela picks catalogue · 2026-10-21

The local Sela picks index contains 227 unique, English-language Project Gutenberg records. It stores metadata and each book's primary Gutenberg page; full text is fetched only after the user selects **Download & add to shelf**. Topic chips show counts computed from the records' tags. This is an editorial set informed by Project Gutenberg's curated shelves and Top 100, not a frozen reproduction of a live top-200 ranking. Public-domain status is jurisdiction-specific; see the [catalogue research note](sela-picks-research.md) and [Project Gutenberg terms](https://www.gutenberg.org/policy/terms_of_use).
